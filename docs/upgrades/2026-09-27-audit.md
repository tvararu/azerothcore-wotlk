## 8. Playerbots decision — facts

- **Adds**: 1,500 bot characters on 150 accounts; ~393 online; AH bot;
  playerbots command server on 8888 (external tools); GM reply patch;
  bots are world "population" that Peon's evals must tolerate (the eval
  grader already has a `blocked` verdict for "playerbot interference").
- **Costs**: 5.7 GiB RSS, ~1 core busy at idle; 76 MB playerbots DB plus
  most of the 78 MB characters DB; startup still 10 s; a fork of the core
  that lags azerothcore/master (7 days now; 1,023 commits accumulated since
  July) and a patch that breaks on upgrades.
- **Clean switch to upstream AC + module?** Not yet. The fork still carries
  145 non-merge commits, ~1,500 lines over 69 files in `src/` (a
  `PlayerbotsScript` hook set, `WorldSession` and `ScriptMgr` changes, DBC
  structures). mod-playerbots is moving toward plain core: #2793 (module DB
  API now in core), #2767 (remove forward declarations that needed core
  changes), #2692 (replace fork-specific calls). Without Playerbots, the
  core is plain azerothcore/master and the other 4 modules work on it.
- **Many Peon instances instead of bots**: each Peon is a real client
  session (no server-side AI cost), but the 1,500 characters' world
  presence would go. SOAP can mass-create accounts (the factory already
  does this).
- **Server-side Peon as a module**: the relevant reusable parts are the
  `PlayerbotsScript` hooks, bot session handling (a `WorldSession` with no
  socket), and `PlayerbotCommandServer` (TCP command channel). Not explored.
